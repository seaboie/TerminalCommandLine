# For ::: Mac (M1/M2/M3/M4 หรือ Intel ที่มี QuickSync) 

## แปลงไฟล์ `MOV` to `MP4` และย่อขนาดไฟล์  



คำสั่งนี้คือการแปลงไฟล์วิดีโอ `img.mov` ให้เป็นไฟล์ `img.mp4` ที่เล็กมากๆ แต่ยังชัดอยู่ โดยใช้ชิปของเครื่อง Mac โดยตรง มาดูทีละตัวแบบละเอียดเลย

```bash
ffmpeg -i img.mov -c:v hevc_videotoolbox -q:v 68 -c:a aac -b:a 128k -tag:v hvc1 -vf scale=1280:720 img.mp4
```

### 1. `ffmpeg` และ `-i img.mov`
**ตัวโปรแกรมและไฟล์ต้นทาง**
* `ffmpeg` = เรียกโปรแกรม ffmpeg
* `-i img.mov` = Input file คือไฟล์ `img.mov` ที่จะเอามาแปลง

### 2. `-c:v hevc_videotoolbox`
นี่คือหัวใจของคำสั่งนี้

* `-c:v` = Codec Video = จะเข้ารหัสภาพด้วยตัวไหน
* `hevc_videotoolbox` = ใช้ **HEVC / H.265** แต่เข้ารหัสด้วย **VideoToolbox** ซึ่งเป็น Hardware Encoder ของ Apple

ต่างจาก `libx265` ยังไง?
* `libx265` = ใช้ CPU ล้วนๆ ช้า แต่บีบได้เล็กและสวยกว่า 10-20%
* `hevc_videotoolbox` = ใช้ชิป GPU / Media Engine ใน Mac (M1/M2/M3/M4 หรือ Intel ที่มี QuickSync) เร็วมาก เร็วกว่า 10-50 เท่า ประหยัดแบต แต่ไฟล์จะใหญ่กว่า `libx265` นิดหน่อยในคุณภาพเท่ากัน

ถ้าเครื่องคุณไม่ใช่ Mac คำสั่งนี้จะ error ทันที

### 3. `-q:v 68`
**ตัวควบคุมคุณภาพ**

สำหรับ encoder ของ Apple จะไม่ใช้ `-crf` เหมือน `libx265` แต่ใช้ `-q:v`

* ช่วงค่าคือ 0-100
* 0 = แย่สุด ไฟล์เล็กสุด
* 100 = ดีสุด ไฟล์ใหญ่สุด
* `68` = ถือว่าคุณภาพกลาง-สูง เป็นค่าที่คนใช้กันเยอะสุดสำหรับลงโซเชียล ส่งไลน์

ถ้าคุณอยากได้ชัดกว่านี้ให้เพิ่มเป็น `75-80` ถ้าอยากได้ไฟล์เล็กกว่านี้ให้ลดเหลือ `60-65`  
ยิ่งเพิ่ม ไฟล์ยิ่งใหญ่ขึ้นแบบทวีคูณ

### 4. `-vf scale=1280:720`
**Video Filter = ปรับขนาดภาพ**

* `-vf` = Video Filter
* `scale=1280:720` = ย่อ/ขยายภาพให้เป็นความละเอียด **720p (HD)** กว้าง 1280 สูง 720 พิกเซล

ทำไมต้องใส่? เพราะ `img.mov` ของคุณอาจจะเป็น 4K มาอยู่แล้ว ถ้าย่อลงมาเป็น 720p ไฟล์จะเล็กลง 3-4 เท่าทันที โดยที่ดูบนมือถือยังชัดพอ

ข้อควรระวัง: ถ้าต้นฉบับเป็นแนวตั้ง 9:16 การสั่ง `1280:720` ตรงๆ มันจะยืดภาพ แบบที่ดีกว่าคือใช้ `scale=-2:720` หรือ `scale=1280:-2` เพื่อให้มันรักษาสัดส่วนอัตโนมัติ

### 5. `-c:a aac -b:a 128k`
**จัดการเรื่องเสียง**

* `-c:a aac` = แปลงเสียงเป็น AAC ซึ่งเป็นมาตรฐานของ MP4
* `-b:a 128k` = Bitrate เสียง 128 kbps ถือเป็นมาตรฐานสากล เสียงชัด ไฟล์ไม่ใหญ่ (ถ้าเป็นแค่เสียงพูด ลดเหลือ 96k ก็พอ)

ถ้าต้นฉบับไม่มีเสียง ส่วนนี้ก็ไม่มีผลอะไร ffmpeg จะข้ามไปเอง

### 6. `-tag:v hvc1`
**ตัวนี้สำคัญมาก แต่คนชอบลืม**

`-tag` คือการ **"ติดป้ายชื่อหลอก"** ให้กับ Stream ในไฟล์ MP4

เพื่อให้เครื่องเล่นเข้าใจว่านี่คือไฟล์แบบไหน

มาละเอียดเลย:

#### 1. โครงสร้างไฟล์ MP4 มันมี 2 ชั้น

นึกภาพกล่องไปรษณีย์นะ

1.  **ข้างในกล่อง (Codec):** คือวิธีบีบอัดจริงๆ เช่น `hevc` คือวิธีบีบอัดแบบ H.265
2.  **ป้ายหน้ากล่อง (Tag / FourCC):** คือป้าย 4 ตัวอักษรแปะไว้หน้ากล่อง บอกคนรับว่า "ข้างในกล่องนี้คือของแบบนี้นะ"

เครื่องเล่นอย่าง iPhone, QuickTime, Chrome มันจะไมแกะกล่องดูก่อน มันดูแค่ป้ายหน้ากล่องก่อนเลย

คำสั่ง `-tag` ใน ffmpeg คือคำสั่งสำหรับ **เขียนป้ายหน้ากล่องเอง**

ไวยากรณ์คือ:
```
-tag:[ประเภท] [ชื่อป้าย]
```
* `v` = video
* `a` = audio
* `s` = subtitle

ดังนั้น `-tag:v hvc1` แปลว่า = "สำหรับสตรีมวิดีโอ ให้แปะป้ายชื่อว่า `hvc1`"

#### 2. แล้วทำไมต้องเป็น `hvc1` ? ในเมื่อ Codec ก็เป็น HEVC อยู่แล้ว?

นี่คือจุดปวดหัวของวงการวิดีโอเลย

HEVC มีป้ายอยู่ 2 แบบที่ถูกต้องตามมาตรฐานทั้งคู่คือ `hev1` กับ `hvc1`

แต่ทำงานต่างกันนิดเดียว:

**`hev1` (แบบเก่า):** เอาข้อมูลสำคัญที่ต้องใช้ถอดรหัสวิดีโอ (ที่เรียกว่า VPS/SPS/PPS) ยัดไว้ในทุกๆเฟรมเลย เปลืองที่นิดหน่อย แต่ยืดหยุ่น

**`hvc1` (แบบใหม่ที่ Apple บังคับใช้):** เอาข้อมูลสำคัญนั้นไปเก็บไว้ที่หัวไฟล์ MP4 ที่เดียวเลย ไม่ยัดซ้ำไปมา

**ปัญหา:** Apple ทั้งหมด - iPhone, iPad, Mac, QuickTime, Final Cut Pro, Safari - เขียนกฏไว้เลยว่า **"ถ้าป้ายไม่ใช่ `hvc1` กูจะไม่เล่น"**

ถ้าคุณเข้ารหัสด้วย `hevc_videotoolbox` โดยไม่ใส่ `-tag:v hvc1` ffmpeg บางเวอร์ชันจะแปะป้ายเป็น `hev1` ให้เองอัตโนมัติ

ผลคือ:
ไฟล์เปิดบน VLC บนคอมเล่นได้ปกติ แต่พอส่งให้เพื่อนที่ใช้ iPhone, อัพขึ้น IG Story, หรือลากเข้า Final Cut จะจอดำ มีแต่เสียง หรือขึ้นว่าไฟล์เสีย

ดังนั้นการใส่ `-tag:v hvc1` คือการสั่งว่า "มึงช่วยแปะป้ายแบบที่ Apple ชอบให้หน่อย จะได้ไม่มีปัญหา"

#### 3. ตัวอย่างป้ายอื่นๆ ที่คุณเจอบ่อย

```bash
-tag:v avc1  # สำหรับ H.264 อันนี้มาตรฐานเลย ต้องใส่ avc1
-tag:v hvc1  # สำหรับ H.265 / HEVC ต้องใส่ hvc1 ถ้าจะให้ iPhone เล่นได้
-tag:a mp4a  # สำหรับเสียง AAC
```

คุณสามารถเช็คได้ว่าไฟล์คุณแปะป้ายอะไรอยู่ด้วยคำสั่งนี้:

```bash
ffprobe -v error -select_streams v:0 -show_entries stream=codec_name,codec_tag_string -of default -i img.mp4
```
ถ้าขึ้น `codec_tag_string=hvc1` คือถูกต้องแล้ว

**สรุปสั้นๆ:**

> `-c:v hevc_videotoolbox` = บอกว่าจะบีบอัดด้วยวิธีไหน (วิธีทำ)
> `-tag:v hvc1` = บอกว่าจะแปะป้ายหน้ากล่องว่าอะไร (ชื่อเรียกเพื่อให้เครื่องอื่นยอมรับ)

ตัวแรกคือของจริง ตัวที่สองคือมารยาททางสังคมเพื่อให้คุยกับชาว Apple รู้เรื่องครับ

### 7. `img.mp4`
ชื่อไฟล์ Output ที่จะได้

### สรุปภาพรวมที่คำสั่งนี้ทำ
> เอาไฟล์ `img.mov` ที่อาจจะใหญ่มาก -> ย่อขนาดเหลือ 720p -> เข้ารหัสภาพใหม่ด้วย H.265 แบบใช้ชิป Mac ให้เร็วๆ ที่คุณภาพ 68 -> แปลงเสียงเป็น AAC 128k -> เซฟเป็น `img.mp4` แบบที่ iPhone เปิดได้ชัวร์ๆ

ผลลัพธ์ที่ได้ ไฟล์จะเล็กกว่าเดิมประมาณ 60-80% เลย

#### ถ้าอยากปรับให้ดีขึ้นอีกนิด แนะนำเวอร์ชันนี้:

```bash
ffmpeg -i img.mov -c:v hevc_videotoolbox -q:v 70 -c:a aac -b:a 128k -tag:v hvc1 -vf "scale=-2:720" -allow_sw 1 img.mp4
```
ที่เพิ่มมาคือ:
* `scale=-2:720` = รักษาสัดส่วนภาพ ไม่ยืด
* `-allow_sw 1` = ถ้าชิป Hardware ทำไม่ไหว ให้ยอมใช้ Software ช่วย จะได้ไม่ error
* `q:v 70` = เพิ่มความชัดขึ้นอีกนิด เผื่อเอาไปโพสต์ IG/FB แล้วโดนบีบซ้ำ
