## ภาพรวม: คำสั่งนี้ทำอะไร

```bash
ffmpeg -i age_encrypt.mp4 -c:v libx264 -preset slow -crf 23 -c:a aac -b:a 128k -movflags +faststart age_encrypt_final.mp4
```

แปลเป็นภาษาคนได้ว่า:

> “เปิดไฟล์ `age_encrypt.mp4` แล้วบีบอัดภาพใหม่เป็น H.264 โดยใช้วิธีที่ประมวลผลค่อนข้างช้าเพื่อเพิ่มประสิทธิภาพการบีบอัด ตั้งระดับคุณภาพภาพไว้ที่ CRF 23 แปลงเสียงเป็น AAC ที่บิตเรตเป้าหมาย 128 kbps จากนั้นจัดโครงสร้าง MP4 ให้เหมาะกับการเริ่มเล่นผ่านเว็บ และบันทึกเป็น `age_encrypt_final.mp4`”

**ประเด็นสำคัญ:** คำสั่งนี้เป็นการแปลงและบีบอัดวิดีโอ ไม่ใช่การเข้ารหัสลับหรือถอดรหัสลับ แม้ชื่อไฟล์จะมีคำว่า `encrypt` ก็ตาม

### 1. แยกคำสั่งออกเป็นแต่ละส่วน

| ส่วนของคำสั่ง | ความหมาย | มีผลต่ออะไร |
|---|---|---|
| `ffmpeg` | เรียกโปรแกรม FFmpeg | เริ่มการประมวลผล |
| `-i age_encrypt.mp4` | ระบุไฟล์ต้นฉบับ | ไฟล์ที่นำมาอ่าน |
| `-c:v libx264` | ใช้ตัวเข้ารหัสวิดีโอ x264 เพื่อสร้างภาพแบบ H.264 | รูปแบบการบีบอัดภาพ |
| `-preset slow` | ใช้ชุดการตั้งค่าที่เน้นประสิทธิภาพการบีบอัด แลกกับเวลาประมวลผล | ความเร็วในการแปลงและประสิทธิภาพการบีบอัด |
| `-crf 23` | ตั้งระดับคุณภาพวิดีโอในโหมด CRF | คุณภาพภาพและขนาดข้อมูลภาพ |
| `-c:a aac` | เข้ารหัสเสียงใหม่เป็น AAC | รูปแบบการบีบอัดเสียง |
| `-b:a 128k` | ตั้งบิตเรตเสียงเป้าหมายประมาณ 128 kbps | คุณภาพเสียงและขนาดข้อมูลเสียง |
| `-movflags +faststart` | ย้ายข้อมูลดัชนีของ MP4 ไปไว้ด้านหน้าไฟล์ | ความสะดวกในการเริ่มเล่นผ่านเครือข่าย |
| `age_encrypt_final.mp4` | ชื่อไฟล์ผลลัพธ์ | ตำแหน่งและรูปแบบไฟล์ที่บันทึก |

ต่อไปคือรายละเอียดของแต่ละส่วนครับ

### 2. `ffmpeg` และ `-i age_encrypt.mp4` — เรียกโปรแกรมและเปิดต้นฉบับ

```bash
ffmpeg -i age_encrypt.mp4
```

`ffmpeg` คือโปรแกรมสำหรับอ่าน แปลง บีบอัด และจัดการไฟล์ภาพเคลื่อนไหวกับเสียง

ส่วน `-i` ย่อมาจาก **input** หมายถึง “ไฟล์ที่จะนำมาใช้เป็นต้นทาง”

ในกรณีนี้:

```text
ไฟล์ต้นฉบับ: age_encrypt.mp4
```

FFmpeg จะตรวจสอบว่าในไฟล์มีอะไรอยู่บ้าง เช่น:
- วิดีโอใช้ตัวบีบอัดชนิดใด
- ภาพมีความละเอียดเท่าไร
- มีเสียงหรือไม่
- เสียงมีกี่แทร็กและกี่แชนเนล
- มีคำบรรยายหรือข้อมูลประกอบอื่นหรือไม่

**นามสกุล `.mp4` ไม่ได้บอกว่าภาพข้างในต้องเป็น H.264 เสมอไป** เพราะ MP4 เป็นภาชนะที่เก็บข้อมูลสื่อ ส่วนวิธีบีบอัดภาพและเสียงเป็นอีกเรื่องหนึ่ง

ตัวอย่างความแตกต่าง:

| คำ | บทบาท |
|---|---|
| MP4 | รูปแบบภาชนะไฟล์ หรือ container |
| H.264 | มาตรฐานการบีบอัดวิดีโอ |
| x264 / `libx264` | ตัวเข้ารหัสที่สร้างวิดีโอ H.264 |
| AAC | รูปแบบการบีบอัดเสียง |

รูปแบบการใช้ `-i` และการกำหนดตัวเข้ารหัสภาพกับเสียงแยกกันเป็นโครงสร้างพื้นฐานของคำสั่ง FFmpeg [ffmpeg-api](https://ffmpeg-api.com/learn/ffmpeg/guide/syntax-and-examples)

**เรื่องชื่อไฟล์:** ชื่อในตัวอย่างไม่มีช่องว่าง จึงเขียนโดยไม่ใส่เครื่องหมายคำพูดได้ แต่ถ้าชื่อไฟล์มีช่องว่าง ควรเขียนแบบนี้:

```bash
ffmpeg -i "age encrypt.mp4" ...
```

### 3. `-c:v libx264` — บีบอัดภาพใหม่เป็น H.264

```bash
-c:v libx264
```

แยกความหมายได้ว่า:
- `-c` คือการเลือก codec หรือตัวเข้ารหัส/ถอดรหัสตามตำแหน่งที่ใช้
- `:v` ระบุว่าใช้กับ **video**
- `libx264` คือตัวเข้ารหัสวิดีโอ H.264 ที่เลือกใช้ในคำสั่งนี้

เพราะตัวเลือกนี้อยู่หลังไฟล์ input และก่อนชื่อไฟล์ output จึงเป็นการกำหนด **ตัวเข้ารหัสสำหรับวิดีโอขาออก**

กระบวนการโดยย่อคือ:

```text
วิดีโอที่ถูกบีบอัดอยู่ในต้นฉบับ
          ↓
ถอดรหัสออกมาเป็นเฟรมภาพ
          ↓
เข้ารหัสเฟรมภาพใหม่ด้วย libx264
          ↓
ได้วิดีโอ H.264 สำหรับไฟล์ผลลัพธ์
```

**นี่คือการเข้ารหัสใหม่ หรือ re-encode ไม่ใช่การคัดลอกข้อมูลภาพเดิม**

แม้ว่าต้นฉบับจะเป็น H.264 อยู่แล้ว คำสั่งนี้ก็ยังเข้ารหัสภาพใหม่อีกครั้ง

ผลที่ต้องเข้าใจ:
- ใช้เวลาและกำลังประมวลผล
- ที่ CRF 23 มีการสูญเสียรายละเอียดบางส่วนจากการบีบอัด
- ไฟล์อาจเล็กลงหรือใหญ่ขึ้นก็ได้ ขึ้นอยู่กับต้นฉบับและการตั้งค่า
- H.264 ร่วมกับ AAC ใน MP4 เป็นชุดรูปแบบที่รองรับได้แพร่หลาย แต่ความเข้ากันได้จริงยังขึ้นกับรายละเอียดอื่น เช่น pixel format และ profile ด้วย [ffmpeg-cookbook](https://ffmpeg-cookbook.com/en/articles/video-to-mp4/)

**คำว่า encoding ในที่นี้หมายถึงการแปลงข้อมูลภาพให้อยู่ในรูปแบบการบีบอัด ไม่ได้หมายถึงการตั้งรหัสผ่านให้ไฟล์**

### 4. `-preset slow` — ให้ตัวเข้ารหัสใช้เวลาวิเคราะห์มากขึ้น

```bash
-preset slow
```

`preset` คือชุดการตั้งค่าภายในของตัวเข้ารหัส เช่น วิธีค้นหาการเคลื่อนไหวและวิธีตัดสินใจว่าจะบีบอัดส่วนต่าง ๆ ของภาพอย่างไร

ให้นึกภาพว่า encoder ต้องตัดสินใจว่า:

> “ส่วนนี้คล้ายกับเฟรมก่อนหน้าหรือไม่ และมีวิธีแทนข้อมูลส่วนนี้ให้ใช้บิตน้อยลงได้อย่างไร?”

ถ้าใช้ preset ที่เร็ว โปรแกรมจะใช้วิธีที่ตัดสินใจได้เร็วกว่า  
ถ้าใช้ preset ที่ช้า โปรแกรมจะใช้วิธีวิเคราะห์ที่ซับซ้อนขึ้น

ลำดับ preset ของ x264 จากเร็วไปช้าโดยทั่วไปคือ:

```text
ultrafast → superfast → veryfast → faster → fast
→ medium → slow → slower → veryslow → placebo
```

สำหรับ `slow` ในคำสั่งนี้:

| เรื่อง | ผลที่คาดหวัง |
|---|---|
| เวลาประมวลผล | ใช้เวลามากกว่า preset ที่เร็วกว่า |
| ประสิทธิภาพการบีบอัด | โดยทั่วไปดีขึ้นเมื่อเปรียบเทียบที่คุณภาพใกล้เคียงกัน |
| ความเร็วในการเล่นคลิป | ไม่ได้ทำให้คลิปเล่นช้าลง |
| ความยาวคลิป | ไม่ได้ทำให้คลิปยาวขึ้น |
| ความละเอียดภาพ | ไม่ได้เปลี่ยนโดยตรง |

**ข้อควรระวัง:** ไม่ควรสรุปว่า “ใช้ preset ช้ากว่า ที่ CRF เท่ากัน ไฟล์จะเล็กกว่าเสมอ”

เพราะ preset มีผลต่อทั้งวิธีบีบอัดและลักษณะคุณภาพภาพ ดังนั้นที่ CRF เดียวกัน ขนาดไฟล์และคุณภาพอาจเปลี่ยนไปพร้อมกันได้ ไม่ใช่การเปรียบเทียบที่คุณภาพเท่ากันเป๊ะ [ffmpeg-cookbook](https://ffmpeg-cookbook.com/en/articles/video-to-mp4/)

จำง่าย ๆ:

> **Preset = ยอมให้ใช้เวลาแค่ไหนในการหาวิธีบีบอัด**

### 5. `-crf 23` — ตัวกำหนดระดับคุณภาพภาพ

```bash
-crf 23
```

CRF ย่อมาจาก **Constant Rate Factor**

เป็นโหมดควบคุมการบีบอัดที่เน้นระดับคุณภาพภาพ มากกว่าการบังคับให้ใช้บิตเรตคงที่ตลอดคลิป

หลักการสำคัญคือ:
- **CRF ต่ำลง:** รักษารายละเอียดมากขึ้น โดยทั่วไปไฟล์ใหญ่ขึ้น
- **CRF สูงขึ้น:** บีบอัดมากขึ้น โดยทั่วไปไฟล์เล็กลง แต่รายละเอียดลดลง

สำหรับการใช้งาน x264 แบบ 8 บิตทั่วไป ช่วงที่มักอ้างอิงคือ 0–51 โดย 23 เป็นค่าเริ่มต้น และค่าประมาณ 18–28 เป็นช่วงที่นิยมทดลองใช้งาน ทั้งนี้คุณภาพที่เหมาะสมขึ้นอยู่กับเนื้อหาวิดีโอ [archive](https://web.archive.org/web/20190614232712/https:/trac.ffmpeg.org/wiki/Encode/H.264)

ตัวอย่างแนวทางทดลอง:

| CRF | แนวโน้มคุณภาพ | แนวโน้มขนาดไฟล์ |
|---|---|---|
| `18` | รักษารายละเอียดมาก เหมาะเมื่อให้ความสำคัญกับคุณภาพ | ค่อนข้างใหญ่ |
| `20` | คุณภาพสูง เป็นอีกจุดเริ่มต้นที่น่าลอง | ใหญ่กว่า 23 โดยทั่วไป |
| `23` | จุดเริ่มต้นกลาง ๆ สำหรับงานทั่วไป | สมดุลตามลักษณะเนื้อหา |
| `26` | บีบอัดมากขึ้น อาจเริ่มเห็นรายละเอียดหาย | เล็กลงโดยทั่วไป |
| `28` | เน้นลดขนาดมากขึ้น ควรตรวจภาพจริง | เล็กลงอีกโดยทั่วไป |

ตารางนี้เป็น **แนวโน้มเมื่อใช้ต้นฉบับและการตั้งค่าอื่นเหมือนกัน** ไม่ใช่การรับประกันผล

**เลข 23 ไม่ได้หมายถึง:**
- คุณภาพ 23%
- ความละเอียด 23%
- วิดีโอ 23 เฟรมต่อวินาที
- บิตเรต 23 Mbps
- ขนาดไฟล์เหลือ 23% ของต้นฉบับ

**ทำไม CRF เดียวกัน แต่ขนาดไฟล์ต่างกันมากได้?**

เพราะแต่ละคลิปบีบอัดยากง่ายไม่เท่ากัน เช่น:

| ลักษณะภาพ | แนวโน้มในการบีบอัด |
|---|---|
| สไลด์นิ่งหรือพื้นหลังเรียบ | มักใช้ข้อมูลน้อย |
| คนพูดหน้ากล้องและพื้นหลังไม่เปลี่ยนมาก | มักบีบอัดได้ค่อนข้างดี |
| กีฬา การเคลื่อนไหวเร็ว รายละเอียดเยอะ | มักใช้ข้อมูลมากขึ้น |
| น้ำกระเพื่อม ใบไม้จำนวนมาก ภาพมี noise | มักบีบอัดยาก |

ดังนั้น **CRF 23 ไม่สามารถบอกล่วงหน้าได้ว่าไฟล์สุดท้ายจะมีขนาดกี่ MB**

อีกประเด็นหนึ่งคือ การลด CRF จาก 23 เป็น 18 **ไม่ได้กู้รายละเอียดที่ต้นฉบับสูญเสียไปแล้ว** เพียงช่วยลดการสูญเสียเพิ่มเติมในรอบการเข้ารหัสใหม่นี้

จำง่าย ๆ:

> **CRF = ต้องการรักษารายละเอียดภาพมากแค่ไหน**

### 6. `-c:a aac -b:a 128k` — แปลงเสียงและกำหนดบิตเรต

```bash
-c:a aac -b:a 128k
```

สองตัวเลือกนี้ทำงานร่วมกัน แต่คนละหน้าที่

**`-c:a aac`**
- `:a` หมายถึง audio หรือเสียง
- เลือกเข้ารหัสเสียงใหม่เป็น AAC
- เป็นการบีบอัดเสียงแบบสูญเสียข้อมูล

**`-b:a 128k`**
- `-b` หมายถึง bitrate
- `:a` ระบุว่าเป็น bitrate ของเสียง
- `128k` หมายถึงประมาณ 128,000 บิตต่อวินาที หรือ 128 kbps

**อย่าสับสนระหว่างบิตกับไบต์**
- `128 kbps` คือประมาณ 128 กิโลบิตต่อวินาที
- เมื่อแปลงเป็นไบต์ จะอยู่ที่ประมาณ 16 kB ต่อวินาที
- เสียง 1 นาทีจึงใช้พื้นที่ประมาณ 0.96 MB
- เสียง 10 นาทีจึงใช้พื้นที่ประมาณ 9.6 MB

ตัวเลขนี้คิดเฉพาะข้อมูลเสียงที่บิตเรตดังกล่าว ไม่รวมวิดีโอและข้อมูลโครงสร้างไฟล์ และบิตเรตที่ได้จริงอาจคลาดเคลื่อนจากเป้าหมายเล็กน้อย

**128 kbps เหมาะแค่ไหน?**
- เป็นจุดเริ่มต้นที่ใช้ได้สำหรับเสียงพูดและงานทั่วไป
- ถ้าเป็นเพลงหรือให้ความสำคัญกับรายละเอียดเสียงมาก อาจทดลอง 192 kbps
- ถ้ามีหลายแชนเนล เช่นเสียงรอบทิศทาง ควรพิจารณาบิตเรตใหม่ ไม่ควรถือว่า 128 kbps เหมาะเสมอ

**128k ไม่ได้หมายถึง 128k ต่อแชนเนล** และคำสั่งนี้ก็ไม่ได้สั่งให้เสียงกลายเป็นสเตอริโอ เพราะไม่มี `-ac 2`

นอกจากนี้ ถ้าต้นฉบับเป็น AAC อยู่แล้ว การใช้ `-c:a aac` ก็ยังเป็นการเข้ารหัสเสียงใหม่ ไม่ใช่การเก็บเสียงเดิมไว้โดยไม่เปลี่ยน

### 7. `-movflags +faststart` — จัด MP4 ให้เริ่มเล่นผ่านเว็บได้สะดวกขึ้น

```bash
-movflags +faststart
```

นี่เป็นการปรับ **โครงสร้างไฟล์ MP4** ไม่ใช่การปรับคุณภาพภาพหรือเสียง

ไฟล์ MP4 มีข้อมูลส่วนหนึ่งเรียกว่า **`moov` atom** ซึ่งเก็บข้อมูลสำคัญสำหรับการเล่น เช่น ข้อมูลแทร็ก เวลา และตารางที่ช่วยระบุตำแหน่งข้อมูลสื่อ

โดยทั่วไป FFmpeg อาจเขียนส่วนนี้ไว้ท้ายไฟล์ แล้ว `faststart` จะทำขั้นตอนเพิ่มเติมเพื่อย้ายมาไว้ด้านหน้าไฟล์ [ffmpeg](https://ffmpeg.org/ffmpeg-formats.html)

ภาพแบบย่อ โดยละรายละเอียดส่วนอื่น:

```text
ก่อนจัด faststart:
ข้อมูลระบุชนิดไฟล์ → ข้อมูลภาพและเสียง → ข้อมูลดัชนี moov

หลังจัด faststart:
ข้อมูลระบุชนิดไฟล์ → ข้อมูลดัชนี moov → ข้อมูลภาพและเสียง
```

**ทำไมตำแหน่งนี้จึงสำคัญ?**

เมื่อเปิดไฟล์ผ่านเว็บ โปรแกรมเล่นจะได้รับข้อมูลจากด้านหน้าไฟล์ก่อน หากข้อมูลที่จำเป็นต่อการเริ่มเล่นอยู่ตรงนั้น ก็ช่วยให้เริ่มเล่นระหว่างดาวน์โหลดได้สะดวกขึ้น

อย่างไรก็ตาม พฤติกรรมจริงยังขึ้นอยู่กับโปรแกรมเล่นและเซิร์ฟเวอร์ด้วย เช่น บางระบบสามารถขออ่านข้อมูลช่วงท้ายไฟล์ได้อยู่แล้ว

**สิ่งที่ `faststart` ทำและไม่ทำ**

| เรื่อง | ผลของ `faststart` |
|---|---|
| ย้ายข้อมูลดัชนีไปด้านหน้า | ทำ |
| ช่วยการเริ่มเล่น MP4 ผ่านเครือข่าย | ทำ |
| เพิ่มคุณภาพภาพ | ไม่ทำ |
| ลด CRF | ไม่ทำ |
| ทำให้ขั้นตอนเข้ารหัสภาพเร็วขึ้น | ไม่ทำ |
| แปลงเป็น HLS หรือ DASH | ไม่ทำ |
| ตั้งรหัสผ่านหรือเข้ารหัสลับไฟล์ | ไม่ทำ |

ชื่อ `faststart` จึงหมายถึง **ช่วยให้เริ่มเล่นได้สะดวกหรือเร็วขึ้น** ไม่ใช่ “แปลงไฟล์เร็วขึ้น”

ในทางกลับกัน ตอนท้ายอาจใช้เวลาเพิ่มเล็กน้อยในการจัดตำแหน่งข้อมูลใหม่ และ **ขั้นตอนเพิ่มเติมนี้ไม่ใช่การเข้ารหัสวิดีโอแบบ two-pass เพื่อควบคุมบิตเรต**

### 8. `age_encrypt_final.mp4` — ไฟล์ผลลัพธ์

```bash
age_encrypt_final.mp4
```

นี่คือชื่อไฟล์ที่ FFmpeg จะเขียนออกมา โดยนามสกุล `.mp4` ใช้ระบุรูปแบบ container ของผลลัพธ์

สำหรับคำสั่งนี้ ภายในไฟล์ผลลัพธ์จะมี:
- วิดีโอที่เข้ารหัสด้วย H.264
- เสียงที่เข้ารหัสด้วย AAC หากมีแทร็กเสียงที่ถูกเลือก
- โครงสร้าง MP4 ที่เปิดใช้ `faststart`

**ไฟล์ต้นฉบับจะไม่ถูกแก้ไข** เพราะคำสั่งนี้อ่านจากชื่อหนึ่งและบันทึกไปอีกชื่อหนึ่ง

ถ้ามีไฟล์ `age_encrypt_final.mp4` อยู่แล้ว โดยปกติ FFmpeg จะถามก่อนเขียนทับ เพราะคำสั่งนี้ไม่ได้ใส่ `-y`

### 9. สิ่งที่คำสั่งนี้ไม่ได้กำหนดไว้

ส่วนนี้สำคัญ เพราะหลายคนเข้าใจว่าคำสั่งบีบอัดจะเปลี่ยนทุกอย่างให้โดยอัตโนมัติ

| สิ่งที่อาจสงสัย | พฤติกรรมของคำสั่งนี้ |
|---|---|
| ลดความละเอียดไหม | ไม่ได้สั่งลด เพราะไม่มีตัวกรอง `scale` |
| บังคับให้เป็น 30 fps ไหม | ไม่ได้สั่ง เพราะไม่มีตัวเลือกกำหนดเฟรมเรตใหม่ |
| ตัดความยาวคลิปไหม | ไม่ได้สั่งตัด เพราะไม่มี `-ss` หรือ `-t` |
| บังคับเสียงเป็นสเตอริโอไหม | ไม่ได้สั่ง เพราะไม่มี `-ac 2` |
| กำหนดขนาดสุดท้ายเป็น MB ไหม | ไม่ได้กำหนด ใช้ CRF แทนการล็อกขนาด |
| รับประกันว่าเล็กกว่าต้นฉบับไหม | ไม่รับประกัน |
| เก็บเสียงทุกภาษาและซับทุกแทร็กไหม | ไม่รับประกัน เพราะไม่มีการเลือกแทร็กด้วย `-map` |
| ถอดรหัสลับไฟล์ไหม | ไม่ได้ทำ |

**โดยทั่วไปความละเอียดและลักษณะเฟรมเรตจะอิงต้นฉบับ** แต่รายละเอียดด้านเวลาอาจขึ้นอยู่กับ timestamps และการจัดการของ FFmpeg ด้วย จึงไม่ควรตีความว่าเป็นการคัดลอกเฟรมและข้อมูลทั้งหมดแบบเดิมทุกบิต

ถ้าไฟล์มีหลายภาษา หลายมุมกล้อง หรือหลายแทร็กคำบรรยาย ควรตรวจสอบการเลือกแทร็กเพิ่มเติม เพราะการเลือกอัตโนมัติไม่ได้แปลว่าจะเก็บทุกอย่างไว้

**เหตุใดไฟล์อาจใหญ่กว่าเดิม?**
- ต้นฉบับอาจถูกบีบอัดมาอย่างหนักอยู่แล้ว
- ต้นฉบับอาจใช้ตัวบีบอัดที่มีประสิทธิภาพสูงกว่าในกรณีนั้น
- ระดับ CRF ที่เลือกอาจทำให้ encoder ใช้ข้อมูลมากกว่าต้นฉบับ

ดังนั้น ไม่สามารถดูเพียงคำสั่งนี้แล้วรับรองว่า “ลดขนาดได้กี่เปอร์เซ็นต์”

### 10. ถ้าต้องการปรับผลลัพธ์ ควรแก้ตรงไหน?

**กรณี A: อยากรักษาคุณภาพภาพมากขึ้น**

ลองลด CRF จาก 23 เป็น 20:

```bash
ffmpeg -i age_encrypt.mp4 -c:v libx264 -preset slow -crf 20 -c:a aac -b:a 128k -movflags +faststart age_encrypt_quality.mp4
```

ผลที่คาดหวัง: รายละเอียดภาพดีขึ้นเมื่อเทียบกับ CRF 23 และไฟล์มักใหญ่ขึ้น

**กรณี B: อยากให้ประมวลผลเร็วขึ้น**

ลองเปลี่ยน `slow` เป็น `veryfast`:

```bash
ffmpeg -i age_encrypt.mp4 -c:v libx264 -preset veryfast -crf 23 -c:a aac -b:a 128k -movflags +faststart age_encrypt_quick.mp4
```

ผลที่คาดหวัง: ใช้เวลาประมวลผลน้อยลง แต่ประสิทธิภาพการบีบอัดและลักษณะคุณภาพภาพอาจเปลี่ยนไป

**กรณี C: ต้องการแปลงภาพ แต่ไม่อยากเข้ารหัสเสียงซ้ำ**

### 🔥 🔥 🔥 🔥 🔥 ถ้าเสียงต้นฉบับเข้ากันได้กับ MP4 ให้ใช้ `-c:a copy`:

```bash
ffmpeg -i age_encrypt.mp4 -c:v libx264 -preset slow -crf 23 -c:a copy -movflags +faststart age_encrypt_audio_copy.mp4
```

ผลที่คาดหวัง:
- ภาพยังถูกเข้ารหัสใหม่
- แทร็กเสียงที่ถูกเลือกถูกคัดลอกโดยไม่เข้ารหัสซ้ำ
- คุณภาพเสียงไม่สูญเสียเพิ่มจากการบีบอัดรอบใหม่
- ไม่ต้องใช้ `-b:a 128k` เพราะไม่ได้เข้ารหัสเสียงใหม่

**กรณี D: แค่อยากเพิ่ม faststart โดยไม่เปลี่ยนภาพและเสียง**

ถ้า codec ของแทร็กที่เลือกเข้ากันได้กับ MP4:

```bash
ffmpeg -i age_encrypt.mp4 -c copy -movflags +faststart age_encrypt_faststart.mp4
```

วิธีนี้ไม่เข้ารหัสภาพและเสียงใหม่ จึงมักเร็วกว่าอย่างมาก และไม่สูญเสียคุณภาพจากการเข้ารหัสซ้ำ แต่ **ไม่ได้ทำให้ข้อมูลภาพและเสียงเล็กลงอย่างมีนัยสำคัญ** เพราะยังคัดลอกข้อมูลที่ถูกบีบอัดไว้เดิม [ffmpeg-cookbook](https://ffmpeg-cookbook.com/en/articles/ffmpeg-faststart-web-playback/)

### 11. วิธีทดลองก่อนแปลงทั้งไฟล์

ถ้าไฟล์ยาว แนะนำให้ลองเพียง 60 วินาทีก่อน:

```bash
ffmpeg -i age_encrypt.mp4 -t 60 -c:v libx264 -preset slow -crf 23 -c:a aac -b:a 128k -movflags +faststart age_encrypt_test.mp4
```

ส่วนที่เพิ่มคือ:

```bash
-t 60
```

หมายถึงให้ผลลัพธ์ยาวประมาณ 60 วินาที แทนการประมวลผลทั้งคลิป

จากนั้นตรวจดู:
- ตัวหนังสือเล็ก ๆ ยังอ่านชัดหรือไม่
- ใบหน้าและรายละเอียดพื้นผิวดูเสียไปหรือไม่
- ฉากเคลื่อนไหวเร็วมีภาพแตกหรือเป็นบล็อกหรือไม่
- เสียงพูดและเสียงเพลงฟังยอมรับได้หรือไม่
- เวลาประมวลผลเหมาะกับงานหรือไม่

ควรเลือกช่วงที่เป็นตัวแทนของคลิปจริงด้วย เพราะถ้า 60 วินาทีแรกเป็นภาพนิ่ง แต่ส่วนใหญ่ของคลิปเป็นการเคลื่อนไหวเร็ว ผลทดลองอาจไม่สะท้อนทั้งไฟล์

## สรุปให้จำง่าย

คำสั่งเดิมเป็น **จุดเริ่มต้นที่สมเหตุสมผลสำหรับการแปลงเป็น MP4 แบบ H.264/AAC และเตรียมให้เล่นผ่านเว็บได้สะดวกขึ้น** แต่ต้องตรวจคุณภาพและขนาดที่ได้จริง

ตัวเลือกหลักแบ่งหน้าที่ชัดเจน:

> **`libx264` เลือกรูปแบบการเข้ารหัสภาพ → `slow` เลือกความพยายามในการบีบอัด → `crf 23` เลือกระดับคุณภาพภาพ → `aac 128k` กำหนดเสียง → `faststart` จัดโครงสร้างไฟล์เพื่อการเริ่มเล่น**

**ถ้าจะปรับเพียงอย่างเดียว ให้เริ่มที่ CRF:** ลดเลขเมื่อต้องการรักษาคุณภาพมากขึ้น เพิ่มเลขเมื่อต้องการลดขนาด แล้วเปรียบเทียบจากต้นฉบับเดียวกันครับ
